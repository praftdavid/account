# 프래프트 관리회계 앱 — 설계 문서 (Claude Code 핸드오프용)

> 이 문서는 기존 단일 파일 웹앱을 데이터 백엔드 기반 앱으로 발전시키기 위한 설계 명세다.
> 목적: 결산 단계의 모든 재무정보를 하나의 시스템에서 확인하고, 분개를 자동화한다.

---

## 1. 프로젝트 정의

- **한 줄 정의**: 분개를 입력(또는 업로드로 자동 생성)하면 시산표·재무제표·이익잉여금처분계산서까지 자동 산출하는 프래프트 전용 관리회계 앱.
- **대상**: 주식회사 프래프트(가족 법인). **혼합업종** — 자기자본 투자매매(금융매출) + 전자상거래(상품매출), 부가세 과세사업.
- **회계 처리 기준 (1기 세무사 신고으로 확정)**: 자기자본 매매업으로서 금융업 기준을 준용한다.
  - **투자 실현손익 → 영업(금융매출)** — 매출액에 순액으로 반영
  - **평가손익(미실현) → 자본(기타포괄손익누계액)** — 손익 미경유
  - 이자수익·외환차익/차손 → 영업외
- **포지셔닝**: 더존/WEHAGO 같은 범용 세무회계 ERP를 **대체**하는 것이 아니라, 세무사/더존에 넘기기 전 단계의 **관리회계·의사결정 층**을 채운다. 법정 신고·장부는 세무사가, 이 앱은 그 위에서 실시간 재무 파악과 자동 분개를 담당한다.

## 2. 아키텍처

| 계층 | 선택 | 비고 |
|---|---|---|
| 데이터/백엔드 | 관리형 DB (Supabase = Postgres + 인증 + API) | 영속성·다기기 동기화·인증을 한 계층에서 |

## 3. 범위 (Scope)

### v1 — 뼈대 + 재무제표
- 분개 기능 (수기 입력)
- 계정과목 마스터 (확장 가능 구조)
- 계정별원장
- 잔액시산표 · 합계잔액시산표
- 손익계산서 · 재무상태표 · 손익내역표
- **이익잉여금처분계산서**
- **자본변동표**

### v1.5 — 고난도 티어 (v1 완성 후 착수)
- 현금흐름표 (간접법: 전체 재무제표 재분류 + 비현금 가산 + 운전자본 조정)
- 예상 법인세 산출표 (세무조정: 익금산입·손금불산입)

### 별도 자동화 계층 (코어 이후)
- **자동 분개 파이프라인** (은행·증권 거래내역·잔액증명서 업로드 → 분개 자동 생성) — 6단계는 §6 참조

### 비목표 (Non-goals) — 스코프에 넣지 않는다
- 홈택스 직접 연동 / 전자세금계산서 발행
- 부가세·원천세·급여·4대보험 **신고** (신고는 세무사/더존)
- 실시간 은행 스크래핑(오픈뱅킹·마이데이터) — 대신 "업로드" 방식 사용
- 세법 전체를 자동 추종하는 세무조정
- 영업보고서·감사보고서·주석의 서술형 자동 생성 (숫자 데이터는 앱, 문장은 수기)

## 4. 설계 원칙

1. **하드코딩 금지 · 외부화**: 계정과목은 코드가 아니라 마스터 데이터, 세율·세무조정 규칙은 규칙 데이터로 분리. 개선 = 데이터 추가.
2. **단일 진실원천**: posted 상태의 `journal_lines` 하나가 모든 재무제표의 원천. 나머지는 그 위의 조회(view).
3. **계층은 코드가 아니라 `parent_account_id`로**: 코드는 사람이 읽는 라벨. 계층 계산에 코드 숫자를 파싱하지 않는다.
4. **두 입력 경로, 하나의 저장 구조**: (A) 업로드→자동, (B) 수기 입력 — 방식만 다르고 `journal_lines` 구조는 동일. `source_type`으로 구분.

## 5. 데이터 스키마

> 관계형(Postgres/Supabase). 필드명은 영문 `snake_case`, 한글 설명 병기. PK/FK 명시.

### 핵심 4테이블 (v1 뼈대)

**① accounts (계정과목 마스터)**
- `account_id` (PK)
- `account_code` (계정코드, unique) — 5자리 체계(§7)
- `account_name` (계정명, 한글 값)
- `account_type` (자산/부채/자본/수익/비용)
- `normal_balance` (차변/대변)
- `parent_account_id` (self-FK — 대→중→소→세목 계층)
- `statement_section` (재무제표 표시 구분)
- `std_report_code` (nullable — 국세청 표준재무제표 표준용코드 매핑, 신고 연계용)
- `tax_attribute` (nullable — v1.5 세무조정 대비)
- `is_active` (사용 여부; 삭제 대신 비활성화)

**② fiscal_periods (회계기간)**
- `period_id` (PK) · `fiscal_year` · `period_start` · `period_end`
- `status` (open / closed — 마감 상태; §8)

**③ journal_entries (전표 헤더)**
- `entry_id` (PK) · `entry_no` · `entry_date` · `period_id` (FK)
- `description` (적요)
- `source_type` (manual / auto / **closing** / opening)
- `source_transaction_id` (FK→raw_transactions, nullable — 자동일 때만)
- `status` (draft / posted / void)
- `posted_at`

**④ journal_lines (분개상세)**
- `line_id` (PK) · `entry_id` (FK) · `account_id` (FK)
- `debit_amount` (차변) · `credit_amount` (대변) — 한 줄에 한쪽만 값
- `segment` (nullable — 투자 / 전자상거래 / 공통) ← 혼합업종 부문 태그
- **제약: 한 전표 내 Σ`debit_amount` = Σ`credit_amount`**

### 자동 분개 4테이블

**⑤ financial_accounts (계좌 마스터)**
- `fin_account_id` (PK) · `account_kind` (은행/증권) · `institution_name` · `account_no_masked`
- `linked_gl_account_id` (FK→accounts — 예: 보통예금)

**⑥ raw_transactions (원천 거래 — 원본 보존·불변)**
- `raw_txn_id` (PK) · `fin_account_id` (FK) · `txn_date`
- `amount` (부호: +입금 / −출금) · `memo` · `balance_after`
- `dedup_key` · `import_batch_id`
- `status` (unmapped / mapped / journalized / ignored)
- `generated_entry_id` (FK, nullable)

**⑦ mapping_rules (매핑 규칙 — 외부화)**
- `rule_id` (PK) · `match_type` (적요/상대방/거래유형) · `match_pattern`
- `target_account_id` (FK→accounts) · `priority` · `fin_account_scope` (nullable) · `is_active`

**⑧ balance_snapshots (잔액증명서 앵커)**
- `snapshot_id` (PK) · `fin_account_id` (FK) · `as_of_date` · `certified_balance`

**(부가) import_batches** — 업로드 이력·재처리 추적

### 투자 보조원장 (§8-A 지원)

**⑨ securities_lots (증권 로트/포지션)**
- `lot_id` (PK) · `ticker` · `name` · `acquire_date`
- `quantity` · `unit_cost` (취득단가) · `cost_basis` (취득원가)
- `fair_value` (기말 공정가치) · `unrealized_oci` (누적 평가익 → 33001 대응)
- `status` (open / closed) · `close_date`
- FIFO로 매각분 원가·실현손익·환입 OCI를 산출. `journal_lines`와 매각 전표로 연결.

### 재무제표 파생 (모두 조회로 도출)
- 계정별원장 = `journal_lines` (account 필터, 일자순 + 누적잔액)
- 잔액/합계잔액시산표 = `journal_lines` group by account, Σ차·Σ대
- 재무상태표·손익계산서 = 시산표를 `account_type`·`statement_section`로 집계
- 손익내역표 = 손익계산서 + `parent_account_id` 계층 세부
- 이익잉여금처분계산서·자본변동표 = 자본계정 기초잔액 + 기중 증감 roll-forward (§8)
- **관리 뷰(b)** = `segment`로 group by → 투자/전자상거래 부문별 손익
- **법정·세무 뷰(a) = 표준재무제표** = `segment` 무시하고 전사 합산 + 각 계정을 `std_report_code`로 변환 → 국세청 표준재무제표 서식. (한 번 기록, 두 가지 집계 — 이중 기장 아님)

## 6. 자동 분개 파이프라인 (6단계)

> 핵심 원리: 업로드는 "계좌 내역"이므로 한쪽 다리(현금·예금 증감)는 이미 확정. 자동화는 나머지 상대 계정만 채운다.

1. **수집·정규화(파싱)**: 기관별 파서가 원본을 표준 거래 레코드 {거래일, 계좌, 금액±, 적요, 잔액}로 변환. 원본은 `raw_transactions`에 불변 보존.
2. **중복 제거·앵커 등록**: `dedup_key`로 중복 제거. 잔액증명서를 검증 앵커로 등록.
3. **계정 매핑(분류)**: 우선순위 = ① 결정적 규칙(적요 패턴) ② 구조적 유형(증권 매수/매도/배당/이자) ③ 과거 이력 ④ 미확정 큐. 각 거래에 (제안 계정, 신뢰도) 부착.
4. **복식 완성 + 계좌간 이체 상쇄**: 확정 현금 다리 + 매핑 상대계정 = 완전한 분개. **함정**: 계좌간 이체는 양쪽 계좌에 다 잡히므로 (동일 금액·근접일자) 매칭해 한 건의 대체거래로 합침(수익·비용 아님).
5. **검증·대사(자기검증)**: 전표별 차대 균형 체크 + 파생 잔액을 잔액증명서와 대사 → 불일치 플래그. (자동 회귀 테스트 역할)
6. **사용자 검토·확정**: 자동 분개는 `status=draft`로 적재. 사용자가 수정·분할·승인 → posted 전기. 사용자의 수정은 `mapping_rules`로 피드백(학습 루프).

> **수기 분개 경로는 반드시 병존**: 계좌 이동 없는 내부거래(감가상각, 미지급비용 계상, 이익잉여금 처분, 원천세 예수 등)는 업로드로 잡히지 않으므로 수기 입력.

- **5자리**, 세목에 2자리 부여(장기 관리회계 연속성). 형태: `[대분류 1][중분류 1][소분류 1][세목 2]`
- 첫 자리 = 재무제표 범주 고정: **1**자산 · **2**부채 · **3**자본 · **4**매출(영업수익) · **5**매출원가 · **6**판관비 · **7**영업외수익 · **8**영업외비용 · **9**법인세

## 8. 마감 · 기초잔액 · 투자평가 규칙

### 8-A. 매도가능증권 평가·처분(OCI 재분류)
- **기말 평가**: 공정가치 변동 → `매도가능증권평가익`(33001, 자본/OCI)에 계상. 손익 미경유. 종목별로 누적 관리.
- **매각(실현)**: ① 해당 종목에 쌓인 OCI 잔액을 환입(자본에서 제거) → ② 취득원가 대비 전체 실현손익을 `금융매출`(41002, 영업)로 인식.
- 따라서 종목별 취득원가·평가익 누적을 추적할 **보조 원장(증권 로트/포지션)**이 필요. 기존 앱의 FIFO·매도가능증권·OCI 로직을 이관.

### 8-B. 마감 & 기초잔액
- 연속 복식부기이므로 **전기말 자산·부채·자본 잔액 = 당기초 잔액**. 별도 기초잔액 테이블 불필요.
- **결산 마감 시**:
  - 수익·비용 계정 → 집합손익 거쳐 이익잉여금으로 대체 → 잔액 0 리셋 (당기 손익만 집계)
  - 자산·부채·자본 계정 → 잔액 그대로 차기 이월
  - 이 대체를 `journal_lines`에 **마감 분개 한 건**(`source_type=closing`)으로 기록 → 단일 진실원천 유지
  - `fiscal_periods.status`를 open→closed로 변경
- **개시 분개(`source_type=opening`)**: 기존 앱에서 데이터를 옮겨오는 **최초 1회**에만 사용.
- 이익잉여금처분계산서·자본변동표는 이 구조에서 자본계정 기초잔액 + 기중 증감으로 자연 도출.
